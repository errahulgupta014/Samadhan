# SAMADHAN — addresses and deployment plan

## Address layout

| Address | What it serves | Where it lives in this repo |
|---|---|---|
| `https://smadhan.com` | A one-page marketing site | `site/` (plain HTML, no build step) |
| `https://test.smadhan.com/` | The administrator portal: sign-in page, then the portal | `app/` (the Next/vinext project in the repo root) |
| `https://test.smadhan.com/app/` | The resident mobile app, running in the phone browser (installable to the home screen) | built into `public/app/` by `node scripts/mobile-web.mjs` |
| `https://test.smadhan.com/api/...` | The server API used by both the portal and the app | `app/api/` |

Old addresses forward automatically: `/admin` → `/`, `/citizen` → `/app/`, `/mobile-app/...` → `/app/...`.
The portal and the app share one origin, so the app finds its server with `window.location.origin` and no address needs to be configured for the web version.

> **Check the spelling of the domain.** The product is SAMADHAN, but the domain you named is **smadhan.com** (one `a` fewer). `site/index.html` uses `smadhan.com` addresses exactly as given. If the real domain is `samadhan.com`, replace `smadhan.com` with it in `site/index.html` (links and contact email) before publishing.

## 1. The one-page site (`smadhan.com`)

Static files in `site/`: `index.html`, `logo.png`, `favicon.png`, `apple-touch-icon.png`, `robots.txt`, `_headers`.
Preview locally: `node scripts/serve-site.mjs` → http://localhost:5180

Suggested hosting: Cloudflare Pages (free), "Upload assets" or Git-connected, build command none, output directory `site`.
Then in Pages → Custom domains add `smadhan.com` (and `www.smadhan.com`, redirecting to the apex).
Before publishing: change the contact address `contact@smadhan.com` in `site/index.html` to a mailbox that exists, and review the wording.

## 2. The portal and the app (`test.smadhan.com`)

Build and publish the project root (the hosting this project was started on publishes the Next/vinext Worker with its D1 database):

```bash
node scripts/mobile-web.mjs   # regenerates public/app (the browser version of the app) — run after any change in mobile/
npm run build                 # builds the portal and API
```

Then publish with the hosting tool you use and attach the custom domain `test.smadhan.com` to that deployment (Cloudflare: Workers & Pages → the project → Custom domains; the DNS record is created for you when the zone is on Cloudflare).
The database migrations in `drizzle/` are applied by the hosting on publish (locally they were applied by hand).

### Settings to make before real use (server variables)
- `ADMIN_BOOTSTRAP_PASSWORD` — a strong secret. Without it the first sign-in creates the Super Admin `Admin` with the password `Admin` (test default).
- `ADMIN_PLATFORM_IDENTITY=off` — turns off the old platform-header login so only the portal's own username/password sign-in works.
- `OTP_PROVIDER` — unset means TEST OTP MODE: anyone can sign in as any mobile number with the fixed code `123456` (`RESIDENT_TEST_OTP`). Acceptable only for the test site; configure a real SMS/WhatsApp provider before real users.
- Serve only over https (the admin cookie is marked `Secure` on https).
- Change the Super Admin password in the portal (account menu → Change password) and set the universal closure code (Settings → Service settings).

### Home-screen install of the app
Open `https://test.smadhan.com/app/` on the phone. Android Chrome: menu → Install app (offered because the site is https). iPhone Safari: Share → Add to Home Screen.
The manifest, icons and service worker are generated by `scripts/mobile-web.mjs` (icons: `node scripts/make-pwa-icons.mjs`).

### Search engines
The portal and app are test sites: the portal layout already sends `noindex`. Only `smadhan.com` should be indexed.

## 3. Later: store apps (APK/IPA)
Needs an Expo account, a hosted https server (this one), and for iPhone an Apple Developer account. `mobile/eas.json` has the `preview` (APK) and `production` profiles. Build with
`EXPO_PUBLIC_API_URL=https://test.smadhan.com npx eas-cli@latest build -p android --profile preview` (and `-p ios`). The app id `in.samadhan.citizen` is a placeholder.

## What was verified locally (not on the real domains)
Routing (`/` portal, `/app/` app, old addresses forward), the one-page site (desktop and 375 px), the typechecks, unit tests and API tests. Nothing has been deployed: no domain, hosting account or DNS exists yet.
